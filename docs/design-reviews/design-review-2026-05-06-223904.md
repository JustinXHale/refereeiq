## Overall Assessment

### The Good
- Theme is now fully token-driven (`colorScheme.*` throughout) with no stray hex literals in reviewed screens — except the auth flow and a few remaining spots noted below.
- Button hierarchy on the welcome screen is clear and M3-correct: `FilledButton` → `FilledButton.tonal` → `OutlinedButton`.
- Tab navigation is clean; feature-flag-gated tabs prevent broken placeholder screens from reaching users.
- Empty states have been significantly improved across the app with retry affordances.
- Touch targets meet 48 dp minimum on chat prompts, answer options, and cart quantity controls.
- Semantics labels on cart icon badge are present and correct.
- Async safety guards (`if (!mounted) return`) are in place across async loading functions.

### The Concerns
- **Auth flow (login, signup, complete-profile, verify-email) is visually inconsistent** with the rest of the app — still uses `ElevatedButton` with raw hex fills, hardcoded `Colors.black` text, and custom `InputDecoration` that bypasses the global `InputDecorationTheme`.
- **`CompleteProfileScreen._themedInput()`** hard-codes `Colors.black` borders/labels and `Colors.white` fill, making it break on any future dark mode and inconsistent with every other form in the app.
- **Shop `GestureDetector`** on product cards is still using `GestureDetector` instead of `InkWell`, losing the M3 ripple feedback.
- **Shop and `ProductBottomSheet`** still use `Colors.grey` and `ElevatedButton` with `foregroundColor: Colors.black` hardcoded — not from the theme.
- **`VerifyEmailScreen`** duplicates the auth button style mismatch and has a hardcoded `Colors.black` text color on the resend link.
- **Drawer has no close affordance** — no visible way to dismiss without swiping or tapping outside; M3 NavigationDrawer recommends a close button or clearly indicated gesture.
- **Home screen TabBar overrides `labelColor`/`unselectedLabelColor` inline** rather than inheriting from the global `TabBarTheme` added in Wave 1 — causes a stale override that could diverge.
- **Profile screen form fields** use deprecated `value` parameter on `TextFormField` (4 instances flagged by analyzer) and custom input styling that partially bypasses the theme.
- **`Settings` section headers** use `Text` widgets styled as section labels instead of M3 `ListTile`-style or `ListSectionHeader` — visually sparse and inconsistent with M3's settings pattern.
- **No loading skeleton / shimmer** — every loading state is a bare `CircularProgressIndicator` with no context, making the app feel slow during cold Firestore loads.

### The Verdict
**Needs some fixes.** The core app (Sources, Ask Sofia, Challenge, Leaderboard, History) is in a solid, consistent state. The auth flow and shop are the two surfaces that still need a theme and consistency pass before store submission.

## Detailed Feedback

### 1. Auth Flow Button Style Inconsistency
- **What**: `EmailLoginScreen`, `EmailSignUpScreen`, `CompleteProfileScreen`, and `VerifyEmailScreen` all use `ElevatedButton.styleFrom(backgroundColor: Color(0xFFFADC44), foregroundColor: Colors.black)` — a manual re-implementation of the primary button style instead of `FilledButton`.
- **Where**: `email_login_screen.dart` line 150–156; `email_signup_screen.dart` line 122–127; `complete_profile_screen.dart` line 246–251; `verify_email_screen.dart` lines 71–76.
- **Why it matters**: Users experience a subtly different button weight (shadow elevation) on these screens vs. the rest of the app. Hard-coded hex will break if the brand colour changes.
- **How to improve**: Replace all four with `FilledButton` (no `styleFrom` needed — inherits `filledButtonTheme`).
- **Priority**: Should fix

---

### 2. `CompleteProfileScreen._themedInput()` Hard-codes Colors
- **What**: The private `_themedInput()` helper manually sets `labelStyle: TextStyle(color: Colors.black)`, `enabledBorder: OutlineInputBorder(borderSide: BorderSide(color: Colors.black))`, `focusedBorder: OutlineInputBorder(borderSide: BorderSide(color: Colors.black, width: 2))`, and `fillColor: Colors.white`. This fully bypasses `InputDecorationTheme`.
- **Where**: `complete_profile_screen.dart` lines 100–112.
- **Why it matters**: When the app's theme changes (or dark mode is added), these fields will stay black-on-white regardless. It also creates a different visual treatment than every other form in the app.
- **How to improve**: Delete `_themedInput()` and replace callers with `InputDecoration(labelText: label)` — the global theme handles the rest.
- **Priority**: Should fix

---

### 3. Shop Product Cards Use `GestureDetector`
- **What**: `ShopScreen` wraps each product card in a `GestureDetector` instead of `InkWell`.
- **Where**: `shop_screen.dart` line 109.
- **Why it matters**: No ripple feedback. Users can't tell when a tap registers. M3 requires state-layer feedback on interactive surfaces.
- **How to improve**: Replace `GestureDetector` with `InkWell` and add `borderRadius: BorderRadius.circular(8)` to match the card's shape.
- **Priority**: Should fix

---

### 4. `ProductBottomSheet` Hardcoded Colors and Wrong Button Type
- **What**: The product image placeholder uses `Colors.grey` and `Colors.grey[300]`; the price text uses `Colors.grey` directly; the Add to Cart button uses `ElevatedButton` with `foregroundColor: Colors.black`.
- **Where**: `product_bottom_sheet.dart` lines 57–59, 70, 124–133.
- **Why it matters**: Inconsistent with rest of app; bypasses theme tokens; ElevatedButton has a shadow that FilledButton doesn't, creating a different visual weight.
- **How to improve**: Replace placeholder colors with `colorScheme.surfaceContainerHighest`/`colorScheme.outlineVariant`; price text with `colorScheme.onSurfaceVariant`; `ElevatedButton` with `FilledButton`.
- **Priority**: Should fix

---

### 5. Home Screen TabBar Inline Overrides
- **What**: `HomeScreen` sets `labelColor: colorScheme.onPrimary` and `unselectedLabelColor: colorScheme.onPrimary.withValues(alpha: 0.6)` directly on the `TabBar` widget, duplicating what `TabBarTheme` already provides.
- **Where**: `home_screen.dart` lines 110–113.
- **Why it matters**: Two sources of truth. If `TabBarTheme` changes, the home screen won't follow unless this inline override is also updated.
- **How to improve**: Remove the `labelColor` and `unselectedLabelColor` overrides; let the `TabBarTheme` drive them.
- **Priority**: Should fix

---

### 6. `VerifyEmailScreen` Remaining Hard-coded Colors
- **What**: `color: Colors.black` on the email address text and `TextButton` label; `ElevatedButton` with hex fill and `Colors.black` foreground.
- **Where**: `verify_email_screen.dart` lines 67, 73–76, 84–87.
- **Why it matters**: Same theme drift as auth screens above.
- **How to improve**: Replace `ElevatedButton` with `FilledButton`. Remove inline `TextStyle(color: Colors.black)` — it will inherit `onSurface` from theme.
- **Priority**: Should fix

---

### 7. Drawer Missing Close Affordance
- **What**: No close button (`IconButton(Icons.close)`) in the drawer header. The only dismiss mechanism is swiping left or tapping outside.
- **Where**: `app_drawer.dart`
- **Why it matters**: M3 Navigation Drawer guidance recommends a close affordance. Users on accessibility tools (switch access, large display) may struggle to dismiss. Also inconsistent with M3's modal nav drawer pattern.
- **How to improve**: Add an `IconButton(Icons.close)` aligned to the top-right of the drawer header (inside the `Container`).
- **Priority**: Should fix

---

### 8. Settings Section Headers Not Using M3 Pattern
- **What**: Section labels ("Notifications", "Privacy & Data", "Legal") are bare `Text` widgets with manual `fontSize: 16, fontWeight: bold`, sitting outside any `ListTile`. M3 recommends using `ListTile` with `contentPadding` or a dedicated section header row.
- **Where**: `settings_screen.dart` lines 71–77, 84–89, 103–108.
- **Why it matters**: Text alignment doesn't match `ListTile` leading icons, creating a ragged left edge. M3 settings pattern specifies `titleSmall` / `labelMedium` in `onSurfaceVariant` for section dividers.
- **How to improve**: Replace bare `Text` + `SizedBox` with a `Padding(padding: EdgeInsets.fromLTRB(16, 16, 16, 4), child: Text(..., style: Theme.of(context).textTheme.labelMedium?.copyWith(color: colorScheme.onSurfaceVariant)))`.
- **Priority**: Should fix

---

### 9. No Loading Skeleton on Firestore Screens
- **What**: Sources tab, leaderboard, history tab, and profile all show a bare `CircularProgressIndicator()` during load with no contextual placeholder.
- **Where**: Every Firestore-backed screen.
- **Why it matters**: Users don't know if the content is personalized, loading from network, or cached. No skeleton means perceived performance is lower. M3 content placeholder pattern recommends shimmer or representative skeleton shapes.
- **How to improve**: Wrap `CircularProgressIndicator` in a centered column with a brief label like `'Loading...'`, or introduce a simple `shimmer` or grey-box skeleton for list items. (Full shimmer is a dependency add; at minimum add a text label beneath the spinner.)
- **Priority**: Consider later

---

### 10. Drawer Loading State Shows Nothing
- **What**: While `FutureBuilder` in `AppDrawer` is loading the user profile, it renders the drawer with name = "Guest" and no affiliation — misleading, not a true loading state.
- **Where**: `app_drawer.dart` lines 28–31.
- **Why it matters**: Users see "Guest" briefly even when they're signed in with a full profile, causing a trust flicker.
- **How to improve**: Check `snapshot.connectionState == ConnectionState.waiting` and show a shimmer / skeleton row in the header instead of defaulting to "Guest".
- **Priority**: Consider later

---

### 11. `CircularProgressIndicator` inside `ElevatedButton` Has No Size Constraint
- **What**: Auth screens show `CircularProgressIndicator()` directly inside `ElevatedButton` / `FilledButton` when `_loading == true`, with no constrained size — the spinner may overflow.
- **Where**: `email_login_screen.dart` line 158; `email_signup_screen.dart` line 130; `complete_profile_screen.dart` line 253; `verify_email_screen.dart` line 78.
- **Why it matters**: Unconstrained progress indicators inside buttons can render unexpectedly large or trigger layout warnings.
- **How to improve**: Wrap with `SizedBox(width: 20, height: 20, child: CircularProgressIndicator(strokeWidth: 2))`.
- **Priority**: Should fix

---

### 12. `ChoiceChip` in `ShopScreen` Uses `.withValues(alpha: 0.8)` on `primary`
- **What**: The filter chips use `selectedColor: colorScheme.primary.withValues(alpha: 0.8)` — a semi-transparent variant of the primary colour.
- **Where**: `shop_screen.dart` line 80; `product_bottom_sheet.dart` line 88.
- **Why it matters**: Semi-transparent primary on a white surface may fail WCAG AA contrast. The `ChipTheme` already handles selected colour correctly; this manual override contradicts it.
- **How to improve**: Remove `selectedColor` override and let `ChipTheme.selectedColor` (set to `colorScheme.primary`) apply.
- **Priority**: Should fix

---

### 13. `ProductBottomSheet` Quantity Selector Has No Tooltips
- **What**: The `+` and `-` `IconButton`s on the product bottom sheet have no `tooltip`.
- **Where**: `product_bottom_sheet.dart` lines 99, 110.
- **Why it matters**: Accessibility: screen reader users cannot identify the purpose of these buttons.
- **How to improve**: Add `tooltip: 'Decrease quantity'` and `tooltip: 'Increase quantity'` to each.
- **Priority**: Should fix

---

### 14. `WelcomeScreen` Title Color Hard-coded White
- **What**: `'RefereeIQ'` title uses `color: Colors.white` instead of a token.
- **Where**: `welcome_screen.dart` line 67.
- **Why it matters**: Technically `Colors.white` is correct here (dark overlay behind it), but it's not using `colorScheme.onInverseSurface` or a documented rationale — just a magic value that could break.
- **How to improve**: Document intent in a comment, or use `Colors.white` explicitly with a comment: `// white-on-dark-overlay — intentional, not a theme token`.
- **Priority**: Consider later

---

### 15. `ProfileScreen` Deprecated `value` on `TextFormField`
- **What**: 4 `TextFormField` instances use the deprecated `value` parameter instead of `initialValue`.
- **Where**: `profile_screen.dart` lines ~435, ~455.
- **Why it matters**: Will produce warnings and eventually break on Flutter SDK updates.
- **How to improve**: Replace `value:` with `initialValue:`.
- **Priority**: Should fix
